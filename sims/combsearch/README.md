# combsearch

This sim tests search over a combinatorial space. It is built on two principles:

1. **Ambiguity makes a space to search.** Each input maps to many possible outputs, so the space of output combinations across slots grows exponentially with the number of slots.
2. **The search needs a target.** Somewhere in that space is a desired state that the network has to find.

## Task

The task is defined by these quantities (all in `csenv.Config`):

| Symbol | Config | Default | Meaning |
|---|---|---|---|
| k | `NSlots` | 4 | input / output slots (pools) |
| n | `NInputs` | 32 | distinct input patterns |
| G | `NGroups` | 8 | total groups |
| g | `GroupsPer` | 3 | groups each input belongs to (its ambiguity) |
| g_n | `GroupN` | 1 | output patterns per input per group |
| m | `NValid` | 1 | groups shared by all the inputs of an item |

Group membership:

- Each input belongs to a random subset of g of the G groups. Assignment is balanced, so every group has about n·g/G members.
- Each (input, group) pair has its own g_n output patterns.

On each trial:

- Each slot gets a distinct input.
- The **valid groups** are the intersection of the inputs' group sets.
- The target is one output pattern per slot, all from the **same valid group**.

In isolation, each input is consistent with g groups, which gives g·g_n candidate outputs per slot and (g·g_n)ᵏ output combinations. Only the combination of all the inputs identifies the target group.

The two parameters that control the search:

- **`NValid` (m):** only items whose inputs share exactly m groups are used.
  - With m = 1, the target is determined by the inputs (when g_n = 1).
  - With m > 1, the target group is chosen at random on each trial. The network has to commit to one group and keep it across all the slots, which is a symmetry-breaking problem.
- **`GroupN` (g_n):** if > 1, the output within the target group is chosen at random, independently in each slot. This adds per-slot sampling but not coordination across slots.

### Train / test split

Items are ordered input tuples: slots matter, because weights are not shared across slots. Half of the items (`TestPct`) are held out for testing, so the test measures generalization to novel combinations of inputs.

The startup output also reports `test coverage`. This is the proportion of (slot, input, valid group) combinations needed by the test items that also appear in training. Coverage is 1 for the defaults. When it is below 1, some test items need a mapping that was never trained in that slot.

Item counts with G = 8, g = 3 (from `TestSpaceSizes`):

| slots | n | m | items | train | test | coverage |
|---|---|---|---|---|---|---|
| 3 | 32 | 1 | 9060 | 4530 | 4530 | 1 |
| 3 | 32 | 2 | 732 | 366 | 366 | 0.975 |
| 3 | 24 | 1 | 3636 | 1818 | 1818 | 1 |
| 3 | 24 | 2 | 198 | 99 | 99 | 0.92 |
| 4 | 32 | 1 | 91776 | 45888 | 45888 | 1 |
| 4 | 32 | 2 | 1632 | 816 | 816 | 1 |
| 4 | 24 | 2 | 144 | 72 | 72 | 1 |

The defaults are 4 slots and n = 32. With 4 slots, chance coordination is lower (see Statistics), and n = 24 leaves too few m = 2 items.

### Patterns

All patterns come from one vocabulary, generated by `patterns.PermutedBinaryMinDiff`:

- The vocabulary holds n input patterns followed by n·g·g_n output patterns, each `PoolSize`×`PoolSize`.
- `PctAct` (0.2) sets the activity level.
- `MaxOverlap` (0.5) is the maximum proportion of active units that any two patterns share.

Slots use the same vocabulary. This doesn't matter, because each slot has its own weights. More patterns need a larger `PoolSize`. The defaults (128 patterns in 7×7 pools, 10 active, at most 5 shared) meet the constraint.

## Network

```
Output  [1, k, 7, 7]  Target
   ↕ PoolOneToOne
Encode  [1, k, 8, 8]  ↔ full ↔  Hidden [12, 12]
   ↑ PoolOneToOne
Input   [1, k, 7, 7]
```

- The slots are the pools along the outer X axis.
- Encode pools connect one-to-one with their Input and Output pools, so each column on its own sees only its own slot.
- Hidden is fully and bidirectionally connected with Encode. It is the only route for coordinating the group choice across slots.
- Layer sizes are set by `EncodeSize` and `HiddenSize` in the sim `Params` config.

## Statistics

Each slot of the Output minus-phase activity is matched to the closest output pattern in the vocabulary by cosine (`csenv.CSEnv.TrialStats`).

| Stat | Meaning |
|---|---|
| `Miss` | proportion of slots whose closest pattern has a cosine below `MatchThr` (0.5), or belongs to a different input |
| `Valid` | proportion of slots that produce an output of their input in one of the valid groups |
| `Coherent` | 1 if all the slots produce outputs of their inputs from the same group (valid or not) |
| `Solved` | 1 if all the slots produce outputs from the same valid group: the search target |
| `MatchCos` | mean cosine of the best matches, as a measure of output pattern quality |

Baselines on the test items with the defaults (from `TestStats`):

| Strategy | Valid | Coherent / Solved |
|---|---|---|
| random one of the input's groups in each slot, m = 1 | 0.34 | 0.009 |
| random one of the input's groups in each slot, m = 2 | 0.66 | 0.021 |
| random valid group in each slot, m = 1 | 1 | 1 |
| random valid group in each slot, m = 2 | 1 | 0.112 |

So:

- With m = 1, `Valid` above 1/g shows the network is using the other slots.
- With m = 2, `Solved` above about 0.11 (about 2·(1/2)⁴ = 0.125; 0.25 with 3 slots) shows the network is coordinating its choice across slots, rather than finding the valid groups independently in each slot.

## First run

Settings: 3 slots, n = 24 (the earlier defaults), default params, 1 run, 30 epochs of 512 trials, NData 16, about 3.5 minutes on the GPU.

- The network learns the input to candidate-output mapping in each slot: train `Miss` falls from 0.95 to about 0.07, and test from 0.32 to 0.07. So it generalizes at the level of single slots.
- `Valid` is about 0.33 (train and test) and `Solved` about 0.03-0.04. Both are at the random-group-per-slot baseline (0.34, 0.043).
- So far it picks one of the input's groups independently in each slot. The coordination through Hidden has not yet been learned.
- `MatchCos` is about 0.67, so the outputs are noisy or partially blended patterns.

The parameters have not been tuned yet.
