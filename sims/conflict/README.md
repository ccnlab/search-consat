# conflict

This tests what the network produces when its inputs conflict. It is trained only on *consistent* inputs that all map to the same output, and then tested with inputs from two groups that map to different outputs. The question is whether the network chooses one of the outputs, with a probability in proportion to the evidence for it, or produces a blend.

## Task

- There are G groups (`NGroups`, default 5), each with its own output pattern.
- Each group has g input patterns (`GroupN`, default 4), all of which map to the group's output pattern. By default, they are variations on a group prototype (see Patterns).
- The input has k slots (`NSlots`, default 4).

**Training:** each trial chooses a group at random, and fills each slot with one of its input patterns (with replacement). The target is the group's output pattern. There is never any conflict in training.

**Testing:** c of the k slots have inputs from a second group B, and the other k − c from group A, for c = 0 to k/2 (the number of conflicting inputs). c = 0 is the same as training: it checks that whatever noise is used doesn't disrupt the trained mapping.

- `TestPerLevel` (default 200) random items are tested for each c, with random groups, slots, and inputs: 600 items for k = 4. 0 tests all of the items: for k = 2 (with g = 4), that is 80 consistent and 320 conflict items, but for k = 4 it is 37,120 items. What matters for the precision of the probability stats is the number of trials per level, `TestPerLevel` × `TestReps`: 4,000 by default, for a standard error of about 0.008 at p = 0.5.
- Each test runs through the whole list `TestReps` times (default 20), in a new random order each time. The activity carries over from one trial to the next in axon, so the residual activity from the previous trial acts as a natural source of noise across reps.
- The test items are divided among the `NData` parallel envs.

**Frequencies:** `Freqs` sets the relative frequency of each of the g inputs within each group, which is used for sampling the training inputs. Empty means they are all equally frequent (the default).

## Expected probabilities

The expected probability of choosing a group is in proportion to the evidence for it: the summed frequency of its inputs, divided by the total over all the slots. With equal frequencies this is (number of slots) / k. For k = 2, the targets are 1.0 for c = 0 and 0.5 / 0.5 for c = 1. For k = 3, they are 1.0 and ⅔ / ⅓.

The stats for each target probability are named by its rounded percent: `P100`, `P50`, `P67`, `P33`, etc. Frequencies and k can be designed to target other probabilities.

## Patterns

- The input patterns are `PoolSize`×`PoolSize` (7×7), with `PctAct` (0.2) = 10 active units.
- With `Prototypes` (the default), the input patterns of each group are generated from a group prototype, so that the mapping from inputs to groups is systematic: inputs of the same group are similar. With fully random input patterns, the mapping is a memorization problem, even though it is linearly separable.
  - The G prototypes are generated by `patterns.PermutedBinaryMinDiff`, with at most `ProtoMaxOverlap` (0.2) of the active units shared between any two: 2 of 10.
  - Each input pattern is its prototype with `FlipPct` (0.2) of the active units turned off (2), and the same number of inactive units turned on, by `patterns.FlipBits`. So each input shares 8 of its 10 active units with its prototype. The inputs of a group are distinct.
  - Inputs of the same group share 6–9 active units, and inputs of different groups 0–4 (with g = 4).
- The patterns are saved in the sim's tensorfs, in `Patterns`: the input patterns of each group in `Items/G0`, `Items/G1`, ..., the prototypes in `Prototypes/G0`, ..., and the output patterns in `Outputs`.
- `Stats/Patterns/DistMatrix` has the distance (1 − cosine) between all of the input patterns, in group order, shown in the `Pattern Distances` grid tab. For these binary patterns, it is 1 minus the proportion of active units shared.
- Without `Prototypes`, the input patterns are independent random patterns from `patterns.PermutedBinaryMinDiff`, as in combsearch, with at most `MaxOverlap` (0.5) of the active units shared between any two.
- The output layer is `NGroups` wide and `NPerOutput` (6) tall. Each group's output pattern is a vertical bar in its column, so the choice is easy to see, and is represented redundantly across the units of the bar.
- `RandOutput` uses random output patterns with the same number of active units instead, as a sanity check. The stats match the output against the patterns by cosine either way.

## Network

```
Output    [NPerOutput, NGroups]   Target
   ↕ full                ↖ Shortcut (↘ EncoderBack)
Hidden1   [20, 20]                 |
   ↕ full                          |
Encoder1  [1, k, 12, 12]   ────────┘
   ↑ pool one-to-one
Input     [1, k, 7, 7]
```

- `NEncoder` (default 1) sets the number of encoder layers (`Encoder1`, ...), each with one pool per input slot, of size `EncoderSize`. They have pool-to-pool (one-to-one) connections: Forward from the Input, and bidirectional between encoder layers, so each slot is encoded separately. `EncoderLateral` adds lateral connections within each pool. The encoder layers have the `Encoder` class for params.
- `NHidden` (default 1) sets the number of hidden layers (`Hidden1`, ...), fully connected bidirectionally in a stack above the encoders, of size `HiddenSize`. `Lateral` adds full lateral connections within each hidden layer.
- Either can be 0: with no hidden layers, the Output is connected bidirectionally to the last encoder layer, and with neither, the Input connects directly to the Output.
- With both encoder and hidden layers, `Shortcut` adds full Forward connections from the last encoder layer to the Output (class `Shortcut`), and `EncoderBack` adds full Back connections from the Output to it (class `EncoderBack`, and `BackPath`).
- `OutputLateral` adds full lateral connections within the Output layer. All of the optional pathways are off by default.
- The params are from pcomb.

## Running

Training runs for a fixed number of `Epochs`, so the weights keep getting stronger after the mapping is learned. The test then runs once, at the end of each run. `TestInterval` > 0 also tests every that many epochs during training, to see how the responses to conflict change with training.

In the GUI, the `Config` button applies changes made to the `Config` settings without restarting the sim: it makes new environments, rebuilds the network (with new weights), loops, and stats (resetting all stats data), and then does Init. Only `GPU` and `GUI` cannot be changed this way.

## Statistics

The network is a model of cortex, which only needs to show a reasonable amount of attractor settling toward one output. It is OK for it to have some activity in the alternative outputs: in the brain, a downstream process (e.g., in the basal ganglia) does further cleanup. So the stats are based on the relative activity of the groups, not on producing a clean pattern (`cfenv.CFEnv.TrialStats`):

- The Output minus-phase activity (ActM) is thresholded at `ActThr` (0.1), to ignore low-level activity, and summed over the units of each group's output pattern (its bar). With `RandOutput`, a unit shared by two patterns counts for both.
- **Top** is the input group with the most activity, **Second** is the other input group (on conflict trials), and **Other** is the summed activity of all the groups that are not in the inputs.
- The output is categorized as:
  1. **Intrusion**, if `OtherRatio` = Other / Top > `IntrusionThr` (0.75). The choice is then the most active other group.
  2. **Blend**, if `SecondRatio` = Second / Top > `BlendThr` (0.75), or there is no activity above threshold.
  3. Otherwise, a **choice** of Top.

| Stat | Meaning |
|---|---|
| `P100`, `P50`, ... | Probability of choosing an input group whose expected probability is 100%, 50%, ... Blends and intrusions count as not choosing it. |
| `AbsDiff` | Mean across the target probabilities of \|measured − target\| |
| `In100`, `In50`, ... | Like `P100`, ... but among only the trials where the choice is one of the input groups: blends and intrusions are left out. The shape of the choice curve, apart from the rate of blends and intrusions |
| `InAbsDiff` | `AbsDiff` for the `In` stats |
| `MatchCenter`, `MatchExtreme` | Test only (all three models): the slope of the `In` choice curve, for the complementary target pair closest to 50% (`MatchCenter` = (`In67` − `In33`) / 0.34) and farthest from it short of 100/0 (`MatchExtreme` = (`In83` − `In17`) / 0.66). 1 = probability matching, above 1 = sharper than matching (toward winner-take-all), below 1 = flatter. Two numbers for the shape of the choice curve, to compare across noise types and models |
| `Blend` | Proportion of trials that are blends |
| `Intrusion` | Proportion of trials that are intrusions |
| `SecondRatio` | Second / Top activity, on conflict trials: 0 = only Top, 1 = equal. A blend is above `BlendThr` (0.75) |
| `OtherRatio` | Other / Top activity, capped at 1. An intrusion is above `IntrusionThr` (0.75) |
| `MatchCos` | Cosine between the output and the closest output pattern, as a raw diagnostic |
| `Slot0` | On tied conflict trials (two input groups with equal evidence, e.g., 2:2 for k = 4) with a choice of one of them: 1 if it is the group in slot 0. 0.5 = no slot bias |
| `Slot1`, `Slot2`, ... | The same as `Slot0`, for the group in each of the other slots |
| `SlotRange` | Test only: the range (max − min) of the slot stats across slots: how much the choice on ties depends on which slots the groups are in |
| `RepeatPrev` | On tied conflict trials with a choice, where the previous trial's choice is one of the input groups: 1 if the choice repeats it. 0.5 = no carryover bias |
| `IntrusionPrev` | On intrusion trials where the previous trial's choice is a group that is not in the inputs: 1 if the intrusion is that previous group. 1 / (G − 2) = 0.33 (for G = 5) = no relation to the previous trial |
| `MinorPrevMinor`, `MinorPrevMajor`, `MinorPrevOther` | On unequal conflict trials with a choice of one of the input groups: 1 if the choice is the minority group, split by the previous trial's choice: the minority group, the majority group, or a group not in the inputs. `MinorPrevOther` is the baseline without carryover to either input group |
| `<Layer>_Silent` | For the Encoder, Hidden and Output layers: 1 if no unit has activity above `ActThr` on the trial. A failure to propagate activity: a silent Output is scored as a `Blend`, so these separate the silent trials from real blends of two active groups |
| `<Layer>_CarryMid`, `<Layer>_CarryEnd` | For every layer: the carryover of its state from the previous trial. The cosine of its activity (Mid = `Beta2`, 100 cycles into the minus phase; End = `ActM`) with its previous-trial `ActP` in the same data-parallel stream, minus the mean cosine with the previous `ActP` of the other streams, which run independent sequences: a baseline for the input overlap. 0 = no carryover. `Beta2` is from `CaP`, whose slow integration keeps a small tail of the previous trial's spiking: `Input_CarryMid` (about 0.05, for the clamped input) measures that tail, and `Input_CarryEnd` should be about 0 |
| `LeadSwaps`, `CommitCyc`, `LoserFrac`, `AltCorr`, `Agree50`, `Agree100` | Test only (axon only), on conflict trials with a choice of one of the input groups: the within-trial competition between the two input groups, from the summed Output `CaM` of each group, sampled every `Run.CompeteInterval` (5) cycles of the minus phase. `LeadSwaps`: how many times the leading group changes. `CommitCyc`: the minus phase cycle of the last change (or of the first lead): when the network commits. `LoserFrac`: the losing group's share of the two groups' activity over the second half of the minus phase. `AltCorr`: the correlation of the cycle-to-cycle changes of the two groups after the first 25 cycles: negative = they alternate (multiplexing). `Agree50`, `Agree100`: 1 if the leader at minus phase cycle 50 or 100 is the final choice |
| `LeadSwapsMinor`, `LeadSwapsMajor`, `CommitCycMinor`, `CommitCycMajor` | `LeadSwaps` and `CommitCyc` on unequal conflict trials, split by whether the choice is the minority or the majority group: whether minority choices come from late reversals or from an early lead |
| `Consist` | Test only: the consistency of the choice for the same conflict item across its `TestReps` repetitions: the proportion of repetitions with its most common choice (a blend counts as a choice), averaged over the conflict items. 1 = the same choice every time |
| `TieConsist` | `Consist` for the tied items: 1 = the same choice every time, about 0.59 = a coin flip (for 20 repetitions) |

- The ratios are relative to Top (from 0 to 1), so they average cleanly, and a missing Second or Other gives 0 instead of an infinite ratio.
- The probability stats are computed per trial (the mean over the input groups with that target of whether each was chosen, NaN if none), and averaged over trials.
- The `In` stats are the same per-trial values, with NaN on blend and intrusion trials, so their mean is the probability conditional on choosing an input group. For example, a P67 of 0.57 and P33 of 0.13 with many intrusions is a 0.81 to 0.19 split between the two input groups, which the `In` stats show directly. Because each test item has inputs from only two groups, the two `In` values of an item add up to 1 (e.g., `In67` + `In33` = 1), and `In50` (the ties) is always 0.5. They are shown in the Test epoch plot, and off by default in the Train plots.
- For k = 2, `P50` combines both groups on conflict trials, so it is (1 − `Blend` − `Intrusion`) / 2 on those trials. The symmetry between the two groups is measured by `Slot0`.
- The probability stats do not distinguish between stochastic choices and fixed preferences for specific items: e.g., a P67 of 0.87 could be 13% of the items always going to the minority group. `Consist` and `TieConsist` measure this, from the choices for the same item across the repetitions in a test.
- `Slot0` and `RepeatPrev` only use tied trials, because on trials with unequal evidence (e.g., 3:1 for k = 4), the choice is driven by the evidence: under majority rule, the slot 0 input is in the chosen (majority) group 3/4 of the time, and whether the choice repeats the previous one depends on which group won last time. For k = 2, all conflict trials are ties.
- The slot stats always average to 0.5 across slots, because on a tie half of the slots hold the chosen group. A slot bias comes from the slots having different weights into the hidden layer (each slot has its own Encoder pool), which depends on the random initial weights, so which slots are favored differs across runs. Even with no real bias, `SlotRange` is not 0: with 200 tied items whose choices are fixed by the item, sampling alone gives a standard error of about 0.035 for each slot stat, and a range of about 0.1 across 6 slots (the conflict_rnn without carryover has `SlotRange` 0.08–0.14). Run 0 always has the same initial weights, so single-run experiments all share the same slot bias.
- The competition stats (`LeadSwaps`, ...) are a test of the "perforated attractor" idea (see [notes_perforated_attractor.md](notes_perforated_attractor.md)): if discrete spiking leaves gaps that let the minority group keep competing, the lead should swap more and commit later on close calls, and minority choices should come from late swaps. `CaM` integrates spikes with a time constant of 5 cycles, so the 5-cycle samples follow the spiking of each group closely. On the GPU each sample copies the neuron state back, which slows testing; `CompeteInterval` = 0 turns the stats off. They are in the Test Trial log too, for splitting by item offline.
- The settling "microscope" (`Run.Microscope`, on by default, as in [O'Reilly, Wyatte, Herd et al., 2013](https://randalloreilly.com/papers/OReillyWyatteHerdEtAl13.pdf)) records the `Act` of every layer at the same 5-cycle samples, and plots the cosine of each layer's activity at each sample with its final activity at the end of the minus phase, plus the cosine of the Output with the output patterns of the chosen and the other input group (`OutWin`, `OutLose`). The `Test MicroscopeTrial` tab has the current trial (data-parallel stream 0), for viewing single trials while stepping; `Test Microscope` has the average over the trials of the latest test, with `OutWin` / `OutLose` also split by minority versus majority choice on unequal trials. A layer whose first sample is already well above 0 starts from carryover of the previous trial's state.
- Testing also has the layer activity stats of training (`<Layer>_ActMAvg`, `_ActMMax` and `_MaxGeM`), averaged over the test trials, which are copied into the Train log as `Test_<Layer>_...` for comparison with the training values. They show whether activity propagates as well on the conflict items as on the trained ones.
- `Stats/Test/SecondRatioHist` (the `Test SecondRatioHist` bar plot tab) has the distribution of `SecondRatio` across the conflict trials in testing, in 10 bins from 0 to 1, as the proportion of trials in each bin. The counts are accumulated over all the tests from training epoch `Epochs` / 2 on (including the final test), in each run. Before that, it shows the last test. This distinguishes a mix of clear choices (near 0) and blends (near 1) from a consistent partial preference.
- The Train Epoch and Run logs have the latest test values as `Test_<stat>`: each epoch has the values from the latest test in the run (NaN before the first one), so they plot as a step line. The Run value is from the final test.

## Results

A first run with the pcomb params and the earlier cosine metric (`MatchThr` 0.8), 1 run, 30 epochs of 512 trials (about 1 minute on GPU):

- Training levels off at about 70% clean outputs.
- The carryover is strong: on conflict trials, the choice repeats the previous trial's choice 87% of the time, and 13% of test trials produce the previous group even when it is not in the inputs. The default `Decay.Act` is 0.2.
- With full decay between trials (`Decay.Act` and `Decay.Glong` = 1), the network fails completely (98% blends), so the carryover is what drives the output to a single bar with these params.

### Source of the variability (k = 6)

With `NSlots` = 6 and output laterals, the choice is a graded function of the evidence, and it varies across the repetitions of the same item:

| Noise | P83 | P67 | P50 | P33 | Intrusion | RepeatPrev | Consist | TieConsist |
|---|---|---|---|---|---|---|---|---|
| 0.01 | 1.0 | 0.87 | 0.31 | 0.014 | 0.10 | 0.90 | 0.77 | 0.43 |
| 0 | 1.0 | 0.90 | 0.30 | 0.009 | 0.10 | 0.91 | 0.78 | 0.44 |

- The results are the same without noise, so the variability across repetitions comes from the activity carried over from the previous trial, not from noise: on ties, the choice repeats the previous trial's choice about 90% of the time.
- `TieConsist` is below the 0.59 of a coin flip between the two groups because there are more than two outcomes: intrusions are about 10% of the trials (`IntrusionPrev` measures how many of them are the previous trial's group).
- The backprop baselines are deterministic without carryover ([conflict_ff](../conflict_ff/README.md), and [conflict_rnn](../conflict_rnn/README.md) with `Decay` = 1). With carryover (`Decay` < 1), conflict_rnn also breaks ties by the previous trial, but without intrusions.
