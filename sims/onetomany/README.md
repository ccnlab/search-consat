# onetomany

This is a focused test of learning a one-to-many mapping, which is the per-slot part of the [combsearch](../combsearch/README.md) task.

Probably the most important factor here, which might have changed since last exploring this kind of task, is the output pathway learning mechanism, which just gets hammered down by the constant error signals.

In general, this is not a very plausible learning mechanism biologically. Need to think about alternatives, presumably in terms of the pulvinar predictive learning system.

Synaptic failure doesn't do anything in particular, except impair performance at higher levels.

- There are n input patterns (`NInputs`, default 32).
- Each input has o output patterns of its own (`NOut`, default 2).
- On each trial, one of the inputs is presented (in a permuted order), and the target is one of its o outputs, chosen at random.

A network that learns the mapping should produce one of the input's outputs, cleanly, in the minus phase. Any one of them is correct. Producing the blend of the outputs (the average of the targets) is the failure mode.

With `NOut = 1`, the task is a one-to-one mapping, as a control.

## Patterns

All patterns are in one vocabulary, generated by `patterns.PermutedBinaryMinDiff` as in combsearch:

- The vocabulary holds n input patterns followed by n·o output patterns, each `PoolSize`×`PoolSize` (7×7).
- `PctAct` (0.2) sets the activity level: 10 active units.
- `MaxOverlap` (0.5) is the maximum proportion of active units that any two input patterns, or any two output patterns, share. The inputs and the outputs are generated as two separate sets, because the overlap between an input and an output does not matter.
- With 4 outputs per input, each output has at least 2 exclusive units (not in any other output of the same input), 5.2 on average. With 2 outputs per input, 8 on average.

## Network

```
Output   [7, 7]    Target
   ↕ full
Encode2  [12, 12]
   ↕ full
Encode   [12, 12]
   ↑ full
Input    [7, 7]
```

This is one slot of the combsearch network, with 2D layers, and the slot pool inhibition as layer inhibition with the same `Gi` values. `NHidden` (default 2) sets the number of Encode layers (Encode, Encode2, Encode3, ...), connected bidirectionally in a stack, and `EncodeSize` sets their size. The path from the last one to the Output has the `ToOutput` class.

`OutputLateral` adds full lateral (self) connections within the Output layer (`PathScale.Rel` 0.2), for more competition between the output patterns.

## Statistics

The stats use the same activity-ratio metric as [conflict](../conflict/README.md), not a cosine match to a clean pattern. It is OK for the network to have some activity in the input's other output: a downstream process would clean that up. What matters is that one output clearly dominates (`otmenv.OTMEnv.TrialStats`):

- The Output minus-phase activity (ActM) is thresholded at `ActThr` (0.1), to ignore low-level activity.
- **Top** and **Second** are the input's own outputs with the most and next most activity, as the mean over the units that belong to only one of the input's outputs (the mean, so that outputs with different numbers of exclusive units are comparable). Units shared by two of the input's outputs (up to `MaxOverlap`) count for neither, so a clean output has no Second activity.
- **Other** is the summed activity of the units outside all of the input's outputs.
- The output is categorized as:
  1. **Intrusion**, if `OtherRatio` = Other / Top (summed over all of its units) > `IntrusionThr` (0.5).
  2. **Blend**, if `SecondRatio` = Second / Top > `BlendThr` (0.75), or there is no activity above threshold.
  3. Otherwise, **Valid**: a choice of Top.

| Stat | Meaning |
|---|---|
| `Valid` | 1 if the output is a choice of one of the input's outputs |
| `Blend` | 1 if the output is a blend |
| `Intrusion` | 1 if the output is an intrusion |
| `SecondRatio` | Second / Top activity: 0 = only Top, 1 = equal. A blend is above `BlendThr` (0.75). NaN for `NOut` = 1 |
| `OtherRatio` | Other / Top activity, capped at 1. An intrusion is above `IntrusionThr` (0.5) |
| `MatchCos` | Cosine between the output and the closest output pattern, as a raw diagnostic |

`Stats/Train/SecondRatioHist` (the `Train SecondRatioHist` bar plot tab) has the distribution of `SecondRatio` across training trials, in 10 bins from 0 to 1, as the proportion of trials in each bin. It is highly variable from one epoch to the next, so the counts are accumulated over all the epochs from `Epochs` / 2 on, in each run. Before that, it shows the last epoch. A mean `SecondRatio` around 0.5 could be a mix of clear choices (near 0) and blends (near 1), or a consistent partial preference on every trial, and the histogram distinguishes these.

There is no train / test split, because there are no combinations to generalize to: the Test mode runs the same task without learning.
